## Bug G — CRITICAL: Short-reel closing frame causes silent PASS

### File
`tools/verify_protagonist.py`

### Root Cause
The closing frame timestamp was hardcoded to `"00:00:30"`. For any reel shorter than
30 seconds, `ffmpeg` cannot seek past the video's EOF and returns a non-zero exit code.
`extract_frame_bytes()` returns `None`, which triggers:

```python
if opening_frame is None or closing_frame is None:
    print("Could not extract frames (ffmpeg not available or file corrupt)")
    return True   # ← SILENT PASS
```

The `closing_frame is None` case (bad seek on a short video) is indistinguishable from
`opening_frame is None` (ffmpeg not installed), so **every reel shorter than 30s silently
bypassed protagonist identity checking entirely**.

### Impact
- All sub-30s reels receive a false PASS on protagonist consistency
- The QA JSON report shows `"passed": true` with no indication a frame couldn't be extracted
- Protagonist-swapped reels can pass CI undetected

### Fix
1. Added `get_video_duration()` — probes video duration using `ffprobe`
2. `compute_closing_timestamp(duration)` — returns `max(1s, min(duration−1s, 30s))`
3. Separated `opening_frame is None` and `closing_frame is None` into distinct
   diagnostic branches with accurate error messages
4. Added `probed_duration_seconds` to the QA JSON report

## Bug H — HIGH: `normalise_reel_manifest()` misses `part_*` naming convention

### File
`tools/normalize_manifest.py`

### Root Cause
`normalise_reel_manifest()` built `parts_detail` by globbing only:

```python
part_files = sorted(directory.glob("master_part_*"))
```

Directories using the bare `part_0`, `part_1`, … naming (common in 2026-07-09 era
reels) produce an empty `parts_detail` list. The emitted manifest reports `parts: 0`,
causing downstream `verify_integrity.py` to flag `MISSING PARTS` or `UNTRACKED` on
every subsequent CI run.

### Impact
- Historical reels with `part_*` naming get permanently broken manifests after migration
- CI fails on those directories on every run

### Fix
Glob both naming conventions, deduplicate by filename, sort:

```python
part_files = sorted(
    {f.name: f for f in (
        list(directory.glob("master_part_*")) +
        list(directory.glob("part_*"))
    )}.values()
)
```

## Bug I — LOW: Dead function `sha256_of_bytes()` in `verify_integrity.py`

### File
`tools/verify_integrity.py`

### Root Cause
`sha256_of_bytes(data: bytes) -> str` was defined but never called. All hashing uses
`sha256_of_parts()` (streaming, multi-file). The function created confusion about which
hashing strategy is canonical.

### Fix
Removed the function entirely.
